## 1. Project Overview

RamSleuth v2 is a dual-layer hardware introspection + benchmarking utility for Linux x86_64:

1. **Live memory-controller telemetry** — active trained subtimings, clocks (MCLK / UCLK / FCLK, gear/div modes, GDM/PDM, command rate), CAD-bus drive strengths & terminations, and voltages (AMD via the `ryzen_smu` SMU PM table + the SMN registers; Intel via MCHBAR MMIO), plus SPD EEPROM decode (JEP106 module/die makers, rank, XMP 2.0/3.0, EXPO).
2. **AIDA64-style benchmark engine** — multi-threaded AVX2/AVX-512 non-temporal SIMD bandwidth (Read / Write / Copy × Memory / L3 / L2 / L1) and pointer-chase latency.

End goal: unprivileged TUI (ratatui) and GUI (egui/eframe) frontends served by a privileged daemon. **State of the frontends:** the TUI is complete (Cycle 3); the GUI is **complete (Cycles 6–7)** — the full Grand Design §3.1/§3.2 dashboard **plus the v2.0.0 polish**: the 3-line header (now unit-aware), Zone 1 compact 3-column with explicit `GEAR_DOWN`/`CR` labels + vendor-conditional timing blocks, Zone 2 flat status line + **burn-in mode** with live per-iteration cells, Zone 3 SPD cards with per-generation part numbers, and a **dedicated Graphs window** (native second OS viewport: 5 series, hover crosshair, horizontal pan, 1/5/15/60-min window) — the embedded ~10-minute trend strip is **removed**; polling is **baseline-once** (auto-refresh OFF by default). **All 8 GUI gap items are closed** (Cycle 6) **and the 7 v2.0.0 polish areas are closed** (Cycle 7). ### Key findings recorded (Cycle 5)

1. **The 5950X host runs a G.Skill F4-3600C18-32GVK kit = DDR4-3600** (1800 MHz MCLK set-point) — the kickoff's "DDR4-3200" was nominal/wrong (the SPD's 3200 MT/s *base* speed misled it); the earlier "1792 vs 1800" delta was **transient retraining, not a scaling bug**.
2. **`monitor_cpu` hard-gates its PM-frame path on PM-table version 0x240903** and exits with ZERO frames unless `-f` is passed — this host's table is 0x380805, so the capture must use `monitor_cpu -f` (infinite frame loop → the `timeout` rc=124 kill is the normal capture path).
3. **The ryzen_smu driver leaves `0xffffffff` in `smn_result` on a failed PCI read** (the userspace `read()` still "succeeds") — it is a failure sentinel, never data. Register **0x50200 specifically fails at the PCI level on this firmware (56.78.0)** while 0x50204–0x50264 read fine. The daemon previously decoded bit 11 of the all-ones word as GDM=1 **by coincidence** (P6-10: sentinel → Na; the PM-table parse value survives). The script's set-point falls back to the PM f32 @0x0CC, which is authoritative.
4. **SPD:** density `0x0D` = 16 Gb (vendor/legacy encoding outside the published `0x10..=0x17` family); maker `0xC1` = G.Skill (JEP106) (P6-04).
5. **The tRP mask is 6 bits at bit 16 (21:16)** per the driver reference — the original plan table's 22:16 was a transcription error (the reference wins).
6. **The P6-01 draft had the 0x50200 address bytes swapped** (`00 02 50 00` = 0x500200); the correct LE bytes are `00 02 05 00` — the wrong register is the origin of the live sentinel (P6-09).

## 4. The AMD Telemetry Model (reconciled across Cycles 4–7)

**PM table (P5-15, Cycle 4):** the version is the `TableVersionId` in the sibling `/sys/kernel/ryzen_smu_drv/pm_table_version` file (4-byte LE `u32`), **not** in the blob; the blob is a headerless LE `f32` array, MIN_LEN 0x518 (326 × f32): `VDDCR_SOC` @ 0x0B0 (volts → mV ×1000), `FCLK` @ 0x0C0, `UCLK` @ 0x0C8, `MCLK` @ 0x0CC (MHz); `div_mode` derived (UCLK == MCLK → OneToOne). Accepted versions: Vermeer / Zen 3 (this host; live `0x380805`) + Matisse / Zen 2 sets. The legacy 7.11.x/12.x/13.x match, the u16-region layout, and the blob-header cross-check are gone. **SMN registers (P6-02/03/10, Cycle 5; command-rate slot C6-05, Cycle 6) — the sanctioned channel for what is NOT in the PM table** (the 27 DRAM subtimings, GDM/PDM, command rate, CAD-bus drive strengths/terminations, VDDIO_MEM, VPP):

- **Access:** the driver's `smn` sysfs attr (`/sys/kernel/ryzen_smu_drv/smn`, RW) — a **write-address→read-value** protocol: write the 4-byte LE register address, read the 4-byte LE result, on one `O_RDWR` fd (the libsmu semantics; only the address word is ever written — never a register value). Canonical `ryzen_smu_drv` kobject first, legacy `ryzen_smu` second. **Never raw MMIO.**
- **The verified map (the `monitor_cpu` reference):** `0x50200` (MCLK set-point `(v & 0x7f)/3×100` MHz + **GDM = bit 11** + command rate bit 10 — the command rate is now **stored as `ClockReadout.command_rate`** (Cycle 6, C6-03/04/05: raw 0 → 1T, 1 → 2T, else `Na`; Intel honest `Na`)), `0x50204` (tCL / tRAS / tRCDRD / tRCDWR), `0x50208` (tRC / tRP — **tRP = 6 bits at bit 16 (21:16)**, not the plan table's 22:16), `0x5020C` (tRRDS / tRRDL / tRTP), `0x50210` (tFAW), `0x50214` (tCWL / tWTRS / tWTRL), `0x50218` (tWR), `0x50220` / `0x50224` (the tRDRD / tWRWR quadrant groups), `0x50228` (tWRRD / tRDWR), `0x50254` (tCKE — not stored), `0x50260` (tRFC1 / tRFC2 / tRFC4), `0x50264` (the tRFC mirror; sentinel `0x21060138`). **The +0x100000 two-stage rule:** when the 0x50200 probe reads marker `0x300`, every register (incl. the 0x50200 re-read) is read at base + 0x100000 (the offset is decided by the first read only).

1. **No-panic `Section<T>` contract (P2-02, frozen):** displayable telemetry values are `Section<T> { Value(T), Na(TelemetryError) }`; fallible operations return `TelemetryResult<T>`. `TelemetryError` variants: `UnsupportedHardware`, `UnsupportedVendor`, `DriverMissing`, `InsufficientPrivilege`, `UnknownPmTableVersion`, `NoDevmem`, `NotApplicable`, `InvalidValue(String)`, `Io(String)`. **No `panic!`, no `unwrap()`/`expect()` on hardware-derived data, no unguarded deref** anywhere in the telemetry crate; every `unsafe` block carries `// SAFETY:` and is bounds-checked. The CLI renders every missing value as `N/A (<reason>)` and exits 0.
2. **Direct SMU access — no `ryzen_smu` Rust crate (P2-03, decision D1):** sysfs-first read of the PM table — canonical `/sys/kernel/ryzen_smu_drv/pm_table` (P5-08) with the legacy `/sys/kernel/ryzen_smu/pm_table` as a secondary candidate — plus the sibling `pm_table_version` / `pm_table_size` attrs (§4); fallback open of `/dev/ryzen_smu` + driver ioctl via `nix` (53XU-fork tolerance only). We own the version-guarded PM parse and all mapping. `nix` (features `fs`/`ioctl`/`mman`) is the **only** Phase 2 dependency and the only telemetry dep. Rejected: `ryzen_smu` crate, `memoffset`, serde/serde_json (hand-rolled JSON in the telemetry CLI), clap (std `env::args`).
3. **AMD model FULLY RECONCILED (P5-15 PM table, Cycle 4 + P6-02/03/10 SMN path, Cycle 5 + the command-rate slot, Cycle 6 + the AGESA validator, Cycle 7, §4):** the f32 layout + `TableVersionId` sets are live-verified (1800 MHz + 1.1375 V on the 5950X) and the **27 DRAM subtimings + GDM are now live from the SMN registers** (tick-identical to the `monitor_cpu` reference — VERDICT PASS); the **command rate (0x50200 bit 10) is stored + displayed since Cycle 6** (`ClockReadout.command_rate`, 1T/2T, Intel honest `Na`). **Intel IMC register offsets (P2-07) remain plan-mandated SKELETONS** pending live validation on the i5-6600 (open item 3). CAD/RTT/drive + PDM are honest `Na` until their bitfields are confirmed driver-side (open item 5).
4. **Intel MCHBAR gating (P2-06, decision D4):** `CpuInfo` must be Intel before **any** file/mmap access; `/dev/mem` is mapped **read-only** behind a guard struct that bounds-checks reads and `munmap`s in `Drop`; STRICT_DEVMEM EIO/ENODATA → `InsufficientPrivilege`; missing file → `NoDevmem`. On the AMD host the path returns `Na(UnsupportedVendor)`/`Na(UnsupportedHardware)` and verifiably never touches `/dev/mem`.
5. **SPD is unprivileged (P2-08 / P2-09):** raw `ee1004` sysfs images (512 B DDR4 / 1024 B DDR5); JEP106 module + die makers (continued-ID support), rank bits, part/serial, JEDEC speed, XMP 2.0/3.0 + EXPO profile summaries; a checksum failure skips the profile, never the module; no panic on truncated/garbage data. Live codes reconciled in Cycle 5: density `0x0D` → 16 Gb (vendor/legacy), maker `0xC1` → G.Skill. Cycle 6 (C6-02): `SpdModule` carries `die_maker` / `die_type` / `devices` (the die-type label mapping defaults to `Na` until confirmed — the GUI follow-up list). **Cycle 7 (C7-02/03): the module part-number decode is generation-dependent** — DDR3/DDR2 `0x81..0x91` (unchanged), DDR4 `0x149..0x15D`, DDR5 `0x200..0x220` — and `XMP3_BASE` moved `0x200` → `0x300` (JESD79-5, the DDR5 part/profile collision fixed); decode-internal, the `SpdModule.part`/`serial`/`profiles` shapes are untouched.
6. **Phase 1 checksum conventions (frozen):** read/copy kernels return the **wrapping sum of the buffer's little-endian 64-bit words** (data-sensitive DCE sink; `0` for a zeroed buffer); the scalar fallback has identical semantics; write kernels' frozen return is the **byte counter** (so `checksum == total_bytes` for Write); per-slice word-sums wrapping-add to exactly the whole-buffer checksum (proves the partition has neither overlap nor gap); all tier buffers are 64-byte aligned (`AlignedBuf`); bandwidth cells are **best-of-3** `Instant` timings, latency cells the **median** of 3 runs of a ≥1 M-hop chase over the *materialized* full-tier ring (Memory tier exceeds L3 → true DRAM latency); non-x86_64 latency falls back to `Instant` only (documented precision loss). Cycle 5 (P6-05): sub-4 MiB tiers re-run their kernel `iters = clamp(32 MiB/total, 1..=65536)` times per pass (work/pass ≤ 32 MiB; aggregate = `iters ×` the single-pass value — the per-pass convention is unchanged; large tiers `iters = 1` byte-identical).
7. **CPUID family mapping (P2-01, frozen):** the 5950X reference host reports **family `0x19` → `Amd(Zen3)`** (frozen map: `0x15`→Zen 1, `0x17`→Zen 2, `0x19`→Zen 3, `0x1A`→Zen 4, `0x1C`→Zen 5, else `Unknown`). **Note: desktop Zen 4/5 silicon also reports family `0x19` on some boards, so the AMD PM parse (P2-04) keys on the SMU version — now the exact `TableVersionId` sets (§4) — not on `AmdZen`** — generation ambiguity cannot break the PM layout. Intel: family `0x6` model table covers Skylake (`0x4F`/`0x56`/`0x5E`) through Arrow Lake; unrecognized models → `IntelGen::Unrecognized` (still Intel-gated, not `Unknown`).
8. **Topology & buffers are pure (P1-02 / P1-03):** `detect() -> Result<CpuTopology, TopologyError>` over /sys (SMT siblings filtered; per-CCD L3 slices; total L3); `plan(&CpuTopology) -> BufferPlan` is a pure function (L1 16 KiB, L2 256 KiB, L3 = 50% of a CCD slice, DRAM = max(256 MiB, 3× total L3), latency ring 128 MiB; all 64-byte aligned; safe fallbacks when sysfs fields are missing).
9. **Phase 3/4 privilege + wire contract (Cycle 3, frozen):** one privileged daemon is the **sole privilege boundary** — all hardware I/O (ryzen_smu sysfs/char-dev, MCHBAR `/dev/mem`, ee1004) stays daemon-side; the client/TUI/GUI chain is tokio-free and never touches hardware. Wire: synchronous length-prefixed **Bincode frames** with a **16 MiB `MAX_FRAME_SIZE` guard** over a **0660 Unix socket** (`/run/ramsleuth/ramsleuth.sock`); tokio confined to the daemon (async accept loop + `spawn_blocking` pumps); serde derives on every wire-crossing public type (payloads reused verbatim — no duplication, no boxing of frozen arm shapes). The daemon **inherits the no-panic contract**: any absent driver/privilege/hardware surfaces as structured `Na` sections in the payload — never a crash of the service or the clients. **Cycle 5 added no wire changes** — the SMN data entered the frozen `AmdPmSnapshot` in place (the P5-15 precedent: semantics changed, shape frozen). **Cycle 6 extended the wire for the GUI** (the sanctioned frozen-shape changes, D-C10/D-C11): the `SystemPlatform` struct + `mem_total_gib`, `SystemMemoryTelemetry` `platform`/`total_capacity`/`dimm_sizes`, `SpdModule` `die_maker`/`die_type`/`devices`, and the command-rate path (`AmdPmSnapshot` → `SmnFields` (0x50200 bit 10) → `ClockReadout.command_rate`) — all with the serde/bincode round-trip gates; no other frozen arm shapes touched. **Cycle 7 extended the wire for burn-in (D-1/D-2, the C7-07 atomic co-land):** `Request += StartBurnIn { target, duration_minutes }` (0 = infinite; stop via the existing `CancelBenchmark { run_id }`) + `Response += BurnInProgress(BurnInTick)` — both arms appended, **every existing arm byte-identical** (the normal-bench stream unchanged), all four consumers (client/TUI/GUI/daemon) co-landed with the guards.
10. **The SMN overlay (P6-02/03/10, frozen in Cycle 5; `command_rate` added in Cycle 6):** SMN data enters the frozen snapshot via `apply_smn(&mut snap)` — an **infallible no-panic overlay** that writes **only** `gdm` + the 27 timings + `command_rate` (PM fields, PDM, CAD never touched); DriverMissing = whole-overlay no-op; per-register containment zeroes only the failed register's fields; the driver's `0xffffffff` failed-read sentinel is **never decoded** (probe arm + `read_word` collapse + decode-level `word_at` normalization); the +0x100000 two-stage offset is decided by the **first read only**; the tRP mask is 6 bits at bit 16 (21:16) per the driver reference.
11. **The GUI threading model (Cycle 6, frozen; refined in Cycle 7):** one `RwLock` over the shared `TelemetryData` — the background poller is the **only writer** of the data fields (D6: no render-thread I/O), the render thread is the **only writer** of `settings` (its one permitted write, the settings panel), one guard at a time per thread (no lock-ordering deadlock); the bench command channel + cancel are separate; the poller re-reads the live `settings` (poll interval, refresh gate, socket) every tick — a settings edit retargets the **same running poller**, no restart; the keyboard path (fresh key-downs only, `repeat: false`) is routed through the same `handle_action` as the buttons (behavioral equivalence, D-C7). 1400×900 @ ~60 FPS, no UI-thread blocking. **Cycle 7 (the v2.0.0 polish):** `refresh_enabled` **defaults false** — the poller is **baseline-once** (exactly one fetch per distinct socket, thread-local `baseline_for`, D-8) then gated on the live knobs; the settings combos carry **unique `from_id_source` ids** (the `from_label("")` shared-Id desync is gone, C7-10); the header lines + the Zone 1 clock rows **consume the capacity/clock unit knobs** (C7-11/C7-15); and the **Graphs window** (item 12) is a second native viewport that is a **pure reader** of the shared `TelemetryData` (D6: the poller remains the only writer).
12. **The Graphs window (Cycle 7, frozen):** eframe 0.27.2 **native multi-viewport** — the root re-issues `show_viewport_deferred(GRAPHS_VIEWPORT_ID, …)` **every frame while open** (idempotent — a stable builder produces no delta); the child is a real winit OS window driven by the **one existing event loop** (the glow runtime's desktop path, `set_embed_viewports(false)`), sharing the root `egui::Context` + the `Arc<RwLock<…>>` state as a pure reader, with its own 16 ms repaint cadence; close = the root stops registering (the button clears the shared `Arc<AtomicBool>`) or the child callback sees `ViewportInfo::close_requested()` (the WM X) → the child goes un-`used` → egui's `end_frame` GCs it (the button + the WM X are behaviorally identical, D-C7). The D-3b dedicated-thread fallback (`eframe::run` on a second OS thread) is **rejected by design** — winit's event loop + the Wayland `wl_display` connection are thread-affine (the operator host is Wayland), and it would duplicate the eframe lifecycle/context/style; it remains the documented fallback only if the live gate fails (it has not — the D-3 live run is §5.1). The graph state = a 5-series ring (1800 samples = 60 min @ the 2 s poll, reusing the `history.rs` RingBuffer) recorded by the poller (one sample per successful poll, Na-guarded — no all-NaN holes); the bandwidth series is a **step series** from `latest_memory_read_bw` (D-5 — not a continuous sampler, which would monopolize every pinned core); VDDCR_CPU + CPU temp have no source on this host → honest `N/A (no source)` rows (D-4); the interactivity (window minutes 1/5/15/60, drag-pan, hover crosshair) is session-local render state in the child context's `IdTypeMap`.

## 11. How to Run (quick reference, release)

The QA-verified flow: one privileged daemon; all frontends unprivileged over the socket.

```bash
# Build everything
cargo build --workspace --release

# 1) Daemon — default socket /run/ramsleuth/ramsleuth.sock (root, CAP_SYS_RAWIO via the unit)
sudo target/release/ramsleuth-daemon
#    or unprivileged local dev (0660 socket, SOFT caps probe warns and keeps serving):
target/release/ramsleuth-daemon --socket /tmp/ramsleuth.sock
#    (the dev host runs the daemon this way, manually — no systemd unit installed; §7a)

# 2) CLI client — no sudo needed
target/release/ramsleuth-client -- dump                       # full hardware timings (exit-criterion command; AMD: clocks + VDDCR_SOC + 27 timings + GDM live on this host)
target/release/ramsleuth-client -- status                     # daemon + hardware status
target/release/ramsleuth-client -- bench --tier l3 --mode memory-only
#    with a dev socket:
target/release/ramsleuth-client --socket /tmp/ramsleuth.sock -- dump
#    no daemon running → exit 1 + friendly DaemonDown start hint (never a crash)

# 3) TUI (R = refresh, S = snapshot, Q = quit) / 4) GUI (the full dashboard: refresh OFF by default — one baseline fetch on connect; the Graphs button spawns the second-window trend view; F2 = validation-card PNG, F3 = JSON + bench, Q = quit — keyboard + buttons; the Settings panel)
target/release/ramsleuth-tui
target/release/ramsleuth-gui

# Ground truth (the Cycle 5 cross-check — VERDICT PASS; needs the daemon up + root)
sudo scripts/amd-ground-truth.sh
#    raw reference: sudo monitor_cpu   (PM frame: -f — REQUIRED on this 0x380805 table; SMN one-shot: -m)

# Direct verification CLIs (no daemon; from the Cycle 1/2 lineage)
cargo run -p ramsleuth-bench --release            # [--avx512] [--json]
sudo cargo run -p ramsleuth-telemetry --release   # [--json]; root + ryzen_smu (installed) for live AMD

# systemd (unit shipped at systemd/ramsleuth.service; packaged by the AUR ramsleuth-git — distribution path; the dev host uses the manual run above)
sudo cp systemd/ramsleuth.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now ramsleuth

# Packaging (P5-02…P5-07): makepkg -si from packaging/ramsleuth-git/; optional AMD extra via scripts/install-ryzen-smu-dkms.sh (already installed on this host — §6)
```

`--tier` accepts `memory | l1 | l2 | l3 | full` (default `full`); `--mode` accepts `full | memory-only` (default `full`).

## 12. Operating Protocol Summary (how work runs in this repo)

1. **Strict phased gating:** each cycle compiles + runs + passes its exit criteria before the next starts. Each phase is planned first (`plans/PLAN-PHASE<N>.md`; the Cycle 6 GUI workstream was planned as `plans/PLAN-CYCLE6.md`, Cycle 7 as `plans/PLAN-CYCLE7.md`) with micro-chunks, dependency tags (`[ISOLATED]` / `[COUPLED-TO: …]` / `[CRITICAL-PATH]`), frozen-interface markers, and per-chunk quality gates.
2. **Single-file micro-chunking:** one target source file per chunk, ≤ ~50–100 lines changed; each chunk adds exactly one `mod <name>;` wiring line to `src/lib.rs` (wiring not counted against the budget).
3. **Per-chunk flow:** implement on `branch/chunk-<ID>` (forked from `v2-development`) → in-file unit tests (`#[cfg(test)]`) → clippy `-D warnings` → **per-chunk code review** (lease-signed) → `git merge --no-ff` into `v2-development` → branch pruned. Interface-freeze chunks (`[CRITICAL-PATH]`) merge first; no silent signature changes — changes are a plan edit + rebase. (Cycle 6 refinement, D-C10: a test-fixture-only red window is allowed during a sanctioned wire freeze, closed by the scheduled fixture-ripple chunks with a hard workspace gate at wave end. Cycle 7 scaled it: C7-07 co-landed every production match-site guard in one atomic commit so the workspace never went production-red.)
4. **Lease board:** `DEV_LOG.md` `@@@ ACTIVE_WORKERS @@@` — sign in with target files before work; sign out with `[DONE]`/`FAILED` + one-line decision + ahead-note; update `@@@ CURRENT_STATE @@@`. (Board is empty right now — the Cycle 7 per-lease record is in the working tree, uncommitted.)
5. **Handoffs:** 3-line **Semantic Pulse** — `STATUS` / `DECISION` / `AHEAD`, one short line each. No full-file dumps or code in chat; all detail goes to disk (plans, logs, docs).
6. **QA audit per cycle:** independent pass of every runnable gate (build, tests debug+release, clippy, live CLI runs in multiple privilege/CPU states) → then **compaction**: merge history into `MASTER_LOG.md`, prune chunk branches, reset `DEV_LOG.md`. (Cycle 7: QA audit = PASS-WITH-MANUAL-LIVE-VERIFY — the sudo/display live run is operator-attended; the compaction is in the working tree, uncommitted — §8.)
7. **Safety/fallbacks (hard rule):** unsupported CPU, missing driver, missing privilege, unknown PM-table version, absent `/dev/mem`, failed SMN read (the `0xffffffff` sentinel) → structured `Na(<reason>)`; **never panic, never segfault, never `unwrap`/`expect` on hardware data**; the Intel path never touches `/dev/mem` on non-Intel hardware; non-x86_64 compiles to a documented degraded path.
8. **MSRV:** keep the workspace at **1.75** and the lockfile pins intact unless the decision in §5.4 (O5) is made; the CI `1.75` leg is the continuous MSRV proof.
9. **Docs discipline:** `Docs/` holds the roadmap + spec + this handover + the full scope reference (`FULLSCOPEvsCOMPLETED.md`); `plans/` holds per-phase plans; `MASTER_LOG.md` is the durable record.
