## 1. Project Overview

RamSleuth v2 is a dual-layer hardware introspection + benchmarking utility for Linux x86_64:

1. **Live memory-controller telemetry** — active trained subtimings, clocks (MCLK / UCLK / FCLK, gear/div modes, GDM/PDM, command rate), CAD-bus drive strengths & terminations, and voltages (AMD via the `ryzen_smu` SMU PM table + the SMN registers; Intel via MCHBAR MMIO), plus SPD EEPROM decode (JEP106 module/die makers, rank, XMP 2.0/3.0, EXPO).
2. **AIDA64-style benchmark engine** — multi-threaded AVX2/AVX-512 non-temporal SIMD bandwidth (Read / Write / Copy × Memory / L3 / L2 / L1) and pointer-chase latency.

End goal: unprivileged TUI (ratatui) and GUI (egui/eframe) frontends served by a privileged daemon. **State of the frontends:** the TUI is complete (Cycle 3); the GUI is **complete (Cycle 6, Phase 7)** — the full Grand Design §3.1/§3.2 dashboard: the 3-line header, Zone 1 grouped 2×3 sections + the GDM/CR row, Zone 2 per-cell live bench, Zone 3 SPD cards with die/rank, history sparklines, the settings panel, the F2 validation-card PNG + F3 JSON + keyboard F2/F3/Q + the dynamic socket (§2, §3). **All 8 GUI gap items are closed** (the gap list was `FULLSCOPEvsCOMPLETED.md` §"GUI Gap"). Packaging & distribution — **delivered in Cycle 4 (Phase 5)**. Live AMD verification — **closed in Cycle 5 (Phase 6)** with the ground-truth cross-check **VERDICT PASS** (§2, §3). The backend (daemon/CLI/telemetry/bench) is complete and live-verified; the remaining work is the operator live-run sign-off + the push + the four operator/hardware-gated items (§5).

**Mandate:** 100% pure Rust, Cargo workspace (Edition 2021, resolver 2), Linux x86_64. No C++/Python/JS components.

### Key findings recorded (Cycle 5)

1. **The 5950X host runs a G.Skill F4-3600C18-32GVK kit = DDR4-3600** (1800 MHz MCLK set-point) — the kickoff's "DDR4-3200" was nominal/wrong (the SPD's 3200 MT/s *base* speed misled it); the earlier "1792 vs 1800" delta was **transient retraining, not a scaling bug**.
2. **`monitor_cpu` hard-gates its PM-frame path on PM-table version 0x240903** and exits with ZERO frames unless `-f` is passed — this host's table is 0x380805, so the capture must use `monitor_cpu -f` (infinite frame loop → the `timeout` rc=124 kill is the normal capture path).
3. **The ryzen_smu driver leaves `0xffffffff` in `smn_result` on a failed PCI read** (the userspace `read()` still "succeeds") — it is a failure sentinel, never data. Register **0x50200 specifically fails at the PCI level on this firmware (56.78.0)** while 0x50204–0x50264 read fine. The daemon previously decoded bit 11 of the all-ones word as GDM=1 **by coincidence** (P6-10: sentinel → Na; the PM-table parse value survives). The script's set-point falls back to the PM f32 @0x0CC, which is authoritative.
4. **SPD:** density `0x0D` = 16 Gb (vendor/legacy encoding outside the published `0x10..=0x17` family); maker `0xC1` = G.Skill (JEP106) (P6-04).
5. **The tRP mask is 6 bits at bit 16 (21:16)** per the driver reference — the original plan table's 22:16 was a transcription error (the reference wins).
6. **The P6-01 draft had the 0x50200 address bytes swapped** (`00 02 50 00` = 0x500200); the correct LE bytes are `00 02 05 00` — the wrong register is the origin of the live sentinel (P6-09).

## 4. The AMD Telemetry Model (reconciled across Cycles 4–6)

**PM table (P5-15, Cycle 4):** the version is the `TableVersionId` in the sibling `/sys/kernel/ryzen_smu_drv/pm_table_version` file (4-byte LE `u32`), **not** in the blob; the blob is a headerless LE `f32` array, MIN_LEN 0x518 (326 × f32): `VDDCR_SOC` @ 0x0B0 (volts → mV ×1000), `FCLK` @ 0x0C0, `UCLK` @ 0x0C8, `MCLK` @ 0x0CC (MHz); `div_mode` derived (UCLK == MCLK → OneToOne). Accepted versions: Vermeer / Zen 3 (this host; live `0x380805`) + Matisse / Zen 2 sets. The legacy 7.11.x/12.x/13.x match, the u16-region layout, and the blob-header cross-check are gone. The char-dev `/dev/ryzen_smu` ioctl path (P2-03) is retained as 53XU-fork tolerance only.

**SMN registers (P6-02/03/10, Cycle 5; command-rate slot C6-05, Cycle 6) — the sanctioned channel for what is NOT in the PM table** (the 27 DRAM subtimings, GDM/PDM, command rate, CAD-bus drive strengths/terminations, VDDIO_MEM, VPP):

- **Access:** the driver's `smn` sysfs attr (`/sys/kernel/ryzen_smu_drv/smn`, RW) — a **write-address→read-value** protocol: write the 4-byte LE register address, read the 4-byte LE result, on one `O_RDWR` fd (the libsmu semantics; only the address word is ever written — never a register value). Canonical `ryzen_smu_drv` kobject first, legacy `ryzen_smu` second. **Never raw MMIO.**
- **The verified map (the `monitor_cpu` reference):** `0x50200` (MCLK set-point `(v & 0x7f)/3×100` MHz + **GDM = bit 11** + command rate bit 10 — the command rate is now **stored as `ClockReadout.command_rate`** (Cycle 6, C6-03/04/05: raw 0 → 1T, 1 → 2T, else `Na`; Intel honest `Na`)), `0x50204` (tCL / tRAS / tRCDRD / tRCDWR), `0x50208` (tRC / tRP — **tRP = 6 bits at bit 16 (21:16)**, not the plan table's 22:16), `0x5020C` (tRRDS / tRRDL / tRTP), `0x50210` (tFAW), `0x50214` (tCWL / tWTRS / tWTRL), `0x50218` (tWR), `0x50220` / `0x50224` (the tRDRD / tWRWR quadrant groups), `0x50228` (tWRRD / tRDWR), `0x50254` (tCKE — not stored), `0x50260` (tRFC1 / tRFC2 / tRFC4), `0x50264` (the tRFC mirror; sentinel `0x21060138`). **The +0x100000 two-stage rule:** when the 0x50200 probe reads marker `0x300`, every register (incl. the 0x50200 re-read) is read at base + 0x100000 (the offset is decided by the first read only).
- **The failure sentinel:** `0xffffffff` = a failed PCI/SMU read (the driver's `smn_result` is not updated; the userspace `read()` still succeeds) — it is **never decoded** (per-register containment; a sentinel probe keeps the PM-table parse value, which zeroes gdm/timings/command-rate). On this firmware (56.78.0) **0x50200 fails at the PCI level while 0x50204–0x50264 read fine**, so the set-point falls back to the PM f32 @0x0CC (authoritative) and GDM is confirmed by the three-source cross-check.
- **CAD/RTT/drive + PDM: confirm-or-Na** — their bitfields are **unconfirmed in the ryzen_smu driver source** (the amkillam v0.1.7 audit, P6-02); they stay zeroed → honest `Disabled`/`Na` (no field is ever displayed with an unverified mapping). Pending driver-side confirmation (§5.5).
- **The Cycle 6 GUI wire extensions (the sanctioned frozen-shape changes, D-C10/D-C11 — §9.9):** the `SystemPlatform` struct (DMI + `/proc`-sourced board/BIOS/AGESA + CPU clock, N/A-safe), `SystemMemoryTelemetry` `platform`/`total_capacity`/`dimm_sizes`, `SpdModule` `die_maker`/`die_type`/`devices`, and the command-rate path (`AmdPmSnapshot` raw slot → `SmnFields` (0x50200 bit 10) → `ClockReadout.command_rate`). All landed with the serde/bincode round-trip gates; no other frozen arm shapes touched.
- **Live result (5950X, Cycle 5 close):** MCLK/UCLK/FCLK = 1800 MHz OneToOne, VDDCR_SOC = 1.1375 V, **27/27 DRAM timings + GDM live and tick-identical to `monitor_cpu -m`** (31 active gates; VERDICT PASS).

## 9. Key Architectural Decisions & Frozen Interfaces (carried forward — still accurate)

## 11. How to Run (quick reference, release)

The QA-verified flow: one privileged daemon; all frontends unprivileged over the socket.

```bash
# Build everything
cargo build --workspace --release

# 1) Daemon — default socket /run/ramsleuth/ramsleuth.sock (root, CAP_SYS_RAWIO via the unit)
sudo target/release/ramsleuth-daemon
#    or unprivileged local dev (0660 socket, SOFT caps probe warns and keeps serving):
target/release/ramsleuth-daemon --socket /tmp/ramsleuth.sock
#    (the dev host runs the daemon this way, manually — no systemd unit installed; §7a)

# 2) CLI client — no sudo needed
target/release/ramsleuth-client -- dump                       # full hardware timings (exit-criterion command; AMD: clocks + VDDCR_SOC + 27 timings + GDM live on this host)
target/release/ramsleuth-client -- status                     # daemon + hardware status
target/release/ramsleuth-client -- bench --tier l3 --mode memory-only
#    with a dev socket:
target/release/ramsleuth-client --socket /tmp/ramsleuth.sock -- dump
#    no daemon running → exit 1 + friendly DaemonDown start hint (never a crash)

# 3) TUI (R = refresh, S = snapshot, Q = quit) / 4) GUI (the full dashboard: F2 = validation-card PNG, F3 = JSON + bench, Q = quit — keyboard + buttons; the Settings panel)
target/release/ramsleuth-tui
target/release/ramsleuth-gui

# Ground truth (the Cycle 5 cross-check — VERDICT PASS; needs the daemon up + root)
sudo scripts/amd-ground-truth.sh
#    raw reference: sudo monitor_cpu   (PM frame: -f — REQUIRED on this 0x380805 table; SMN one-shot: -m)

# Direct verification CLIs (no daemon; from the Cycle 1/2 lineage)
cargo run -p ramsleuth-bench --release            # [--avx512] [--json]
sudo cargo run -p ramsleuth-telemetry --release   # [--json]; root + ryzen_smu (installed) for live AMD

# systemd (unit shipped at systemd/ramsleuth.service; packaged by the AUR ramsleuth-git — distribution path; the dev host uses the manual run above)
sudo cp systemd/ramsleuth.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now ramsleuth

# Packaging (P5-02…P5-07): makepkg -si from packaging/ramsleuth-git/; optional AMD extra via scripts/install-ryzen-smu-dkms.sh (already installed on this host — §6)
```

`--tier` accepts `memory | l1 | l2 | l3 | full` (default `full`); `--mode` accepts `full | memory-only` (default `full`).

## 12. Operating Protocol Summary (how work runs in this repo)

1. **Strict phased gating:** each cycle compiles + runs + passes its exit criteria before the next starts. Each phase is planned first (`plans/PLAN-PHASE<N>.md`; the Cycle 6 GUI workstream was planned as `plans/PLAN-CYCLE6.md`) with micro-chunks, dependency tags (`[ISOLATED]` / `[COUPLED-TO: …]` / `[CRITICAL-PATH]`), frozen-interface markers, and per-chunk quality gates.
2. **Single-file micro-chunking:** one target source file per chunk, ≤ ~50–100 lines changed; each chunk adds exactly one `mod <name>;` wiring line to `src/lib.rs` (wiring not counted against the budget).
3. **Per-chunk flow:** implement on `branch/chunk-<ID>` (forked from `v2-development`) → in-file unit tests (`#[cfg(test)]`) → clippy `-D warnings` → **per-chunk code review** (lease-signed) → `git merge --no-ff` into `v2-development` → branch pruned. Interface-freeze chunks (`[CRITICAL-PATH]`) merge first; no silent signature changes — changes are a plan edit + rebase. (Cycle 6 refinement, D-C10: a test-fixture-only red window is allowed during a sanctioned wire freeze, closed by the scheduled fixture-ripple chunks with a hard workspace gate at wave end.)
4. **Lease board:** `DEV_LOG.md` `@@@ ACTIVE_WORKERS @@@` — sign in with target files before work; sign out with `[DONE]`/`FAILED` + one-line decision + ahead-note; update `@@@ CURRENT_STATE @@@`. (Board is empty right now.)
5. **Handoffs:** 3-line **Semantic Pulse** — `STATUS` / `DECISION` / `AHEAD`, one short line each. No full-file dumps or code in chat; all detail goes to disk (plans, logs, docs).
6. **QA audit per cycle:** independent pass of every runnable gate (build, tests debug+release, clippy, live CLI runs in multiple privilege/CPU states) → then **compaction**: merge history into `MASTER_LOG.md`, prune chunk branches, reset `DEV_LOG.md`. (Cycle 6: QA audit = PASS-WITH-MANUAL-LIVE-VERIFY — the sudo/display live run is operator-attended; the compaction is in the working tree, uncommitted.)
7. **Safety/fallbacks (hard rule):** unsupported CPU, missing driver, missing privilege, unknown PM-table version, absent `/dev/mem`, failed SMN read (the `0xffffffff` sentinel) → structured `Na(<reason>)`; **never panic, never segfault, never `unwrap`/`expect` on hardware data**; the Intel path never touches `/dev/mem` on non-Intel hardware; non-x86_64 compiles to a documented degraded path.
8. **MSRV:** keep the workspace at **1.75** and the lockfile pins intact unless the decision in §5.4 (O5) is made; the CI `1.75` leg is the continuous MSRV proof.
9. **Docs discipline:** `Docs/` holds the roadmap + spec + this handover + the full scope reference (`FULLSCOPEvsCOMPLETED.md`); `plans/` holds per-phase plans; `MASTER_LOG.md` is the durable record. Update them every cycle; this document is the standing handover — refresh it at each cycle close-out.
