## 3. FROZEN SHAPES (exact field additions — frozen before implementation; a deviation = plan edit + rebase)

New wire fields take three forms: (a) `Section<T>` per-cell containment (the frozen `error.rs` `Section`/`NaReason`) — e.g. `SpdModule.die_maker`/`die_type`, `ClockReadout.command_rate`, `SystemMemoryTelemetry.total_capacity`; (b) a container of them — `SystemMemoryTelemetry.dimm_sizes: Vec<Section<f64>>` (parallel to `spd`); (c) a new serde-derived struct — `SystemMemoryTelemetry.platform: SystemPlatform`. The only new snapshot-level raw slots are `AmdPmSnapshot.command_rate: u8` and `SmnFields.command_rate: u8` (mirroring the existing `gdm`/`pdm`). Every new wire type is `serde`-derived and rides the bincode round-trip. **`CpuInfo` is NOT changed** (it stays CPUID-pure; its round-trip test is unchanged).

**NEW `SystemPlatform`** — `platform.rs` (a new vendor-neutral branch, DMI + `/proc` sourced, like the SPD branch; each field degrades independently, `collect_platform() -> SystemPlatform` never fails the process). Derives `Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize` (no `Copy` — it holds `String` cells) so it sits in the `SystemMemoryTelemetry` derive chain; **already landed in C6-01** (commit 96bd078):
| field | type | source | fallback |
|---|---|---|---|
| `cpu_clock_mhz` | `Section<f64>` | `/proc/cpuinfo` `cpu MHz` (first core) | `Na(NotApplicable)` if the file/line is absent |
| `motherboard` | `Section<String>` | `/sys/class/dmi/id/board_name` (fallback `board_vendor`, then `product_name`) | `Na(NotApplicable)` (VM/container) |
| `bios` | `Section<String>` | `/sys/class/dmi/id/bios_version` (` + <bios_date>` when present) | `Na(NotApplicable)` |
| `agesa` | `Section<String>` | best-effort AMD AGESA token parsed from the BIOS string, else the `ryzen_smu` `version`/`smu_fw` attr when it carries one | `Na(NotApplicable)` (common — no clean unprivileged AGESA) |

Plus a free fn **`mem_total_gib() -> Section<f64>`** (`/proc/meminfo` `MemTotal` kB → GiB) — the total-capacity fallback (a memory property, so it is a free fn, not a `SystemPlatform` field).

**`SystemMemoryTelemetry`** — `facade.rs` (adds three fields; the existing four stay):
| field | type | computed |
|---|---|---|
| `platform` | `SystemPlatform` | `collect_platform()` (new branch, runs on every vendor) |
| `total_capacity` | `Section<f64>` (GiB) | `sum(dimm_sizes)` when ≥1 DIMM, else `mem_total_gib()`, else `Na` |
| `dimm_sizes` | `Vec<Section<f64>>` (GiB) | parallel to `spd`; per module = `density_mbit × devices / 8192`; `Na` when that module's density or devices is `Na` |

**`SpdModule`** — `spd_decode.rs` (adds three fields; `decode()` populates them):
| field | type | source |
|---|---|---|
| `die_maker` | `Section<String>` | DRAM-die JEP106 from bytes `0x2E`/`0x2F` (DDR5) / `0x100`/`0x101` (DDR4) — the die ID `decode_maker` already reads as a fallback, now carried separately; `Na` when absent |
| `die_type` | `Section<String>` | human die-type label; **default `Na(NotApplicable)`** (a die variant like "A-Die" is not a standard SPD field — a documented die_maker+density→label mapping may be filled in later) |
| `devices` | `Section<u8>` | per-rank device count = byte `0x80` bits 3:0 (`per_rank`); a new `decode_devices` **re-derives** it with `decode_rank`-equivalent invalid-config gating (byte present; `total`/`per_rank` nonzero and `total % per_rank == 0`, else `Na(ParseError)`) — `decode_rank` itself computes `per_rank` but **discards** it (returns `total/per_rank` = the rank count) |

**`ClockReadout`** — `amd_readout.rs` (adds one field):
| field | type | mapped from |
|---|---|---|
| `command_rate` | `Section<CommandRate>` | `AmdPmSnapshot.command_rate`: `0→OneT`, `1→TwoT`, else `Na(ParseError(…))` |

**Intel side (finding 1, D-C11):** the production `ClockReadout{…}` literal in `intel_readout::decode_channel` (L288–296) is a no-`Default` exhaustive literal, so `command_rate` **must** be set there or the telemetry lib breaks with E0063 post-merge (no original chunk touched `intel_readout.rs`). It is set to **`Section::na(NaReason::NotApplicable)`** — the Intel 1N/2N command rate is already surfaced as `div_mode` in this model (frozen P2-07, `decode_cmd_rate` → `div_mode`), so a separate slot would redundantly re-expose the same bits; this mirrors how Intel already carries the AMD-only `gdm`/`pdm` as `Na(NotApplicable)`. This ripple is **co-landed into C6-03** (D-C10).

**NEW `CommandRate`** — `amd_readout.rs`: `#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)] pub enum CommandRate { OneT, TwoT }` (display `1T`/`2T`) — the exact derive chain of `DivMode` (amd_readout.rs L98), so it rides the `ClockReadout` bincode round-trip.

**`AmdPmSnapshot`** — `amd_pm.rs` (adds one raw slot, mirroring `gdm`/`pdm`): `command_rate: u8` (`parse()` leaves `0`; `apply_smn` fills it).

**`SmnFields`** — `amd_smn.rs` (adds one field): `command_rate: u8` (decoded from `0x50200` bit 10 via the existing `command_rate()` extractor — its `#[allow(dead_code)]` is removed).

**The `apply_smn` write-surface change (the only P6-02 frozen-contract extension):** the overlay now writes `gdm` + `timings` + `command_rate` (was `gdm` + `timings` only). Documented in the module + this plan; the sentinel rule (0x50200 `0xFFFFFFFF` read-failure → the field decodes to 0 → honest `Na`) is unchanged and never decodes as data.

## 4. DESIGN DECISIONS (each with a one-line rationale)

- **D-C1 — Platform identity is a new `SystemPlatform` branch, not fields on `CpuInfo`.** `CpuInfo::detect()` is CPUID-pure (no sysfs/DMI); motherboard/BIOS/AGESA/clock are DMI + `/proc` sources, so they belong in an independent vendor-neutral branch that degrades per-field (exactly like the SPD branch), leaving `CpuInfo` and its round-trip test untouched.
- **D-C2 — The command rate is a new `CommandRate` display enum + a raw `AmdPmSnapshot.command_rate` slot, decoded from SMN `0x50200` bit 10 (reusing the existing extractor) and written through `apply_smn`.** The value is already decoded-but-not-stored (P6-02); the honest path is to add the frozen slot + extend the overlay, mirroring exactly how `gdm` flows (raw snapshot → `map_amd` → `Section` display enum) — never a signature change.
- **D-C3 — Per-DIMM capacity = `density_mbit × devices / 8192` GiB; total = Σ per-DIMM with a `/proc/meminfo` `MemTotal` fallback when no SPD modules are present; all degrade to honest `Na`.** The SPD density is per-die and the Rank-Config device count is already parsed, so their product is the module's true capacity; the meminfo fallback keeps the RAM line populated even when the SPD driver is absent (no-panic, no invented data).
- **D-C4 — History/charting: a hand-rolled immediate-mode line plot (no new dependency) over a fixed-capacity ring buffer of `N=300` samples (= 10 min at the 2 s poll), appended by `spawn_poller`.** egui has no built-in chart and the workspace's no-new-deps spirit (MSRV-pinned lockfile) favors a ~40-line `ui.painter()` plot over adding a chart crate; 300 samples is enough for a 10-min trend without unbounded memory.
- **D-C5 — Settings: in-memory only this cycle (a `Settings` struct on `TelemetryData` — poll interval, units, theme — surfaced by a settings panel); the poller reads the live interval each tick; persistence to `$XDG_CONFIG_HOME` is a documented follow-up, not implemented.** Keeps the no-panic / no-new-file-I/O contract and the CLI-only `--socket` surface unchanged; in-memory settings satisfy the "units / theme / refresh controls" gap without a new I/O path to harden.
- **D-C6 — Export parity: F2 becomes a full "validation card" PNG (the header + the 4 zones' key readouts rendered to a larger PNG via the existing `png` encoder — the bench mini-heatmap stays as one component), and F3's JSON gains the bench grid + run state alongside the telemetry (a small `ExportPayload` wrapper).** The spec's F2 is "a clean .png validation card of the dashboard," not the bench grid alone; reusing the existing encoder + the frozen wire payloads (no new deps) closes the parity gap honestly.

The GUI **feature** chunks (C6-20…C6-30) remain strictly one-file with full per-chunk green gates.
- **D-C11 — Intel `ClockReadout.command_rate` = honest `Na(NotApplicable)` (finding 1).** The Intel IMC 1N/2N command rate is already surfaced as `div_mode` in this model (frozen P2-07: `decode_cmd_rate` → `div_mode`, intel_readout.rs L276–281). ## 6. PIPELINE (sliding-window-2, gated — no parked chunks)

**Execution order:** C6-01 → C6-02 → **C6-04 → C6-03** → C6-05 → C6-06 → C6-07 → C6-09 → … → C6-19 → (wave-end `cargo test --workspace`) → C6-20 → … → C6-30, exactly the list order (C6-08 retired in revision 2). Three `[CRITICAL-PATH]` waves: **Wave 1 — data model (C6-01…C6-07)** — the shape chunks co-land their same-crate ripples (D-C10) and all land before the consumer ripple, so the ripple branches fork from the **post-shape-freeze** `v2-development` tip; within the telemetry crate the co-landed files are strictly sequential per shape — `facade.rs` (C6-02→C6-04→C6-03→C6-06), `amd_readout.rs` (C6-04→C6-03), `amd_smn.rs` (C6-04→C6-05), CLI `main.rs` (C6-02→C6-06) — and **C6-04 precedes C6-03** (`map_amd`/`good_snapshot` read `AmdPmSnapshot.command_rate`). **Wave 2 — consumer ripple (C6-09…C6-19)** — relaxed per-chunk gates (D-C10), closed by a single **`cargo test --workspace`** green gate after C6-19. **Wave 3 — GUI features (C6-20…C6-30)** — fork after the ripple is green; strictly one-file with full gates; GUI same-file chains strictly sequential (`COUPLED-TO`): `telemetry_zone.rs` C6-18→C6-21; `status_zone.rs` C6-19→C6-23; `update.rs` C6-17→C6-25→C6-27; `style.rs` C6-28→C6-29; `main.rs` C6-20→C6-30.

**Sliding window 2:** while the implementer works `branch/chunk-c6-NN`, the reviewer works the just-completed `branch/chunk-c6-(N-1)` — the reviewer runs that chunk's verification gate, lease-signs it in `DEV_LOG.md`, `git merge --no-ff`s it into `v2-development`, and prunes the branch. The implementer commits `feat(c6-NN): …` and pushes the branch to origin (local-only; the operator-gated push of `v2-development` itself stays O6).

**Rebase trigger:** after every merge to `v2-development`, the in-flight branch rebases onto the new tip **before** its review (the frozen-shape ripple means a branch that forked before a shape change cannot review against stale fixtures). Because the shape freeze (C6-01…C6-07; C6-08 retired) precedes the ripple, no ripple branch forks before the shapes; a same-file later chunk rebases onto its earlier sibling's merge (a D-C10 shape chunk is rebase-consistent with its same-crate co-landed files by construction). If a rebase reveals a conflict in a FROZEN SHAPE (not just a fixture), stop — it is a plan edit, not a merge.

**Circuit-breaker rule (hard stop):** the pipeline halts and the reviewer returns `STATUS: FAILED` on any of: (a) a **production (non-test) compile failure in any crate at a gate boundary** — `cargo check --workspace` (non-test targets) not clean after a merge (the refined rev-3 hard invariant) — or a failing compile in a telemetry shape chunk, the wave-end `cargo test --workspace`, or a GUI-feature chunk; a **test-fixture-only E0063** in a mid-wave cross-crate crate (client/daemon/tui/gui) caused by a landed shape change and **scheduled to its known ripple chunk (C6-09…C6-19) is expected under the refined D-C10 invariant and does NOT trip** — it is the allowed red window, closed by the ripple + the hard post-C6-19 `cargo test --workspace` gate; (b) `clippy --workspace --all-targets -- -D warnings` non-clean; (c) **any baseline test red at a gate boundary** (371 + the cycle's additions, debug or release) — same D-C10 carve-out as (a): the fully-landed state (telemetry shape `cargo test -p ramsleuth-telemetry` green, the wave-end `cargo test --workspace` green, each GUI-feature `cargo test -p ramsleuth-gui` green) must be green, while a mid-wave cross-crate crate is allowed to be red until its siblings land; (d) a **no-panic / no-segfault** violation (a panic, a `0xFFFFFFFF` sentinel decoded as data, or a crash in any privilege × CPU state); (e) a FROZEN-SHAPE field changed beyond §3 without a plan edit. On a trip: exact diagnostics are written to `DEV_LOG.md`, the offending branch is not merged, and the pipeline resumes only after the defect is fixed and its gate re-run. (No-panic is the workspace's core contract — it is the first thing checked, never waived.)

**No gates / no parking:** unlike Phase 6, nothing here is hardware- or operator-gated. The operator's only role is the final QA live-run (§7) and, if a DMI/AGESA source is absent on the host, accepting its honest N/A (not a gate).
